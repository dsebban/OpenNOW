# Vulkan snapshot fence-wait vs codec split: one bounded experiment (continue)

## 1. Summary

**Verdict: CONTINUE with exactly one bounded experiment, then stop.**

Today's two decoder observables, `call` and `residence`, both include `VulkanCopyPool`'s synchronous `wait_for_fences`. No existing observable can split the 8 ms into codec work and snapshot work.

The smallest discriminator is a per-frame hook inside the existing `DecodeTimingProbe` owner. It records:
- the fence-wait duration;
- whether the decoder's timeline semaphore was still unsignaled when the copy was submitted;
- cumulative sums that give all-frame means.

A side effect is direct proof of backend binding. If the change in snapshot count equals the change in output count, every frame went through the embedded VulkanOnly snapshot path.

The run uses one T6-identical 180 s passive window and a pre-registered decision table. There is no async rewrite, no removal of the wait, no new tool or collector, and no FFI/Qt ABI change.

## 2. Current-state analysis

**Worker data flow (`session.rs`, ~L695–722)**
1. `decode_timings.record_submission(ts)` runs first.
2. `call_started` is taken.
3. `decode_frame(&mut decoder, frame)` or `poll_decoder` runs.
4. `call_duration` is measured.
5. `record_decoded_outputs` stamps `Instant::now()` after the whole call returns.
6. `record_call(call_duration, !frames.is_empty())` runs.
7. `enqueue_frames` runs.

**Inside the decode call (`video/ffmpeg.rs`)**
- `drain` → `convert_frame`.
- When `shared_device` is `Some`, `convert_frame` lazily creates `VulkanCopyPool` and calls `copy()`.

**Inside `copy_frame` (`vulkan_copy.rs`)**
1. Validates the frame.
2. `av_frame_ref` retains the source.
3. Takes FFmpeg `lock_frame`.
4. `submit_copy` waits on the source timeline semaphores (`source_waits`), then copies and signals.
5. `unlock`.
6. Blocks in `wait_for_fences(COPY_TIMEOUT_NS)`.
7. Publishes `with_completed_gpu_copy()`.

**Consequences**
- **Fence wait is inside both observables.** `residence` (submission → post-call output) and `call` both contain the fence wait.
- **Residence ≈ call.** With in-flight 0–1, zero unmatched, and outputs equal to calls, each packet's frame leaves in the same call.
- **The fence wait is not "copy only".** The copy submission GPU-waits on the decoder semaphore values. If FFmpeg returned the frame before its decode submission finished on the GPU, the CPU wait also covers the decode GPU tail. A large wait therefore does not prove that async copy would help. A pending/ready flag per frame is required to attribute it.
- **No binding record.** `DecoderChanged` is emitted only on a change, and the HUD label is generic. However, `VulkanCopyPool::copy` is reachable only with an adopted `SharedVulkanDevice` and `Pixel::VULKAN` frames, so a count of completed copies is a binding proof.

**Reusable pieces**
- `DecodeTimingProbe` / `DecodeTimingAccumulator`: bounded rings, `push_sample`, `summarize`, and cumulative totals retained across `clear()`.
- The decoder's `take_format_change()` pattern, which lets the worker pull side-channel state after each call.
- The T6 build/deploy/observe procedure and its identity proofs.
- The ignored GPU test `shared_vulkan_hevc_p010_gpu_only`, for an on-device smoke test.

**Blocking:** no sub-span exists below `call`. The rolling summaries cover 256-sample windows, not all frames.

## 3a. Design — hook

**`SnapshotTiming`**
- Kind: `pub(crate)` `Copy` struct, defined in `timing.rs`.
- Placed there so it exists without the `vulkan` feature.
- Shape: `{ fence_wait: Duration, source_pending: Option<bool> }`.

**`VulkanCopyPool` changes**
- New field: `timings: Vec<SnapshotTiming>`.
  - Capacity is retained across drains.
  - Pushes are skipped once `len >= MAX_SNAPSHOTS`, as defense against a consumer that never drains.
  - The field is not part of `Retirement`.
- `submit_copy` gains a pending query:
  - It runs after `wait_values` is computed and before the queue `lock`, while the caller holds FFmpeg's frame lock.
  - For each `(sem, value)`, call `device.get_semaphore_counter_value`.
  - `pending = any(counter < value)`.
  - Any query error yields `None`; the error is never propagated and never changes control flow.
  - Return type becomes a private `struct Submitted { signals: Vec<(u64,u64)>, source_pending: Option<bool> }`. It has one call site.
- `copy_frame` timing:
  - Take `Instant::now()` immediately before `wait_for_fences`.
  - On `Ok`, push `SnapshotTiming { elapsed, pending }` right after `self.pending = false`.
  - Timeout or device-lost paths record nothing. They already fail and invalidate.
- New method: `pub(super) fn drain_timings(&mut self, sink: &mut dyn FnMut(SnapshotTiming))`, which calls `sink` for each item via `drain(..)`.

**FFmpeg decoder (`ffmpeg.rs`)**
- Add `drain_snapshot_timings(&mut self, sink: &mut dyn FnMut(SnapshotTiming))`.
  - Under `cfg(feature="vulkan")`: forward to `snapshot_pool` if present.
  - Otherwise: no-op.

**Decoder dispatch type** (wherever `take_format_change` is defined)
- Add the same method. Non-FFmpeg variants (and a trait default, if it is a trait) are no-ops.

**Session worker (`session.rs`)**
- In the `Ok(frames)` arm, after `record_call` and before `enqueue_frames`:
  - `decoder.drain_snapshot_timings(&mut |t| decode_timings.record_snapshot(t))`.
- `Err` arms do not drain. Those decoders are dropped or replaced, and their samples die with them.

**Accumulator (`timing.rs`)**

New accumulator fields:

| Field | Purpose |
|---|---|
| `snapshot_wait_us: VecDeque<u64>` | Ring of fence waits, stored in ns like the existing rings |
| `snapshots_total` | Cumulative count of completed copies |
| `snapshot_ready_total` | Copies whose source decode was already signaled |
| `snapshot_pending_total` | Copies whose source decode was still pending |
| `snapshot_unknown_total` | Copies whose pending query failed |
| `snapshot_wait_total_ns` | Cumulative fence wait, all frames |
| `snapshot_wait_ready_total_ns` | Cumulative fence wait, ready frames only |
| `output_call_total_ns` | Cumulative output-producing call time; added inside existing `record_call` only when `produced_output` |

New `DecodeTimings` fields:
- `snapshot_wait: Option<DecodeStagePercentiles>`
- `snapshot_window_samples`
- each total above, converted to µs

Behavioral rules:
- `clear()` does not reset these, matching the existing cumulative totals and rings.
- `is_empty`, `has_progress` and `progress_reference` are unchanged.
- New probe method: `DecodeTimingProbe::record_snapshot(SnapshotTiming)`.

**Native summary emitter** (location unknown, see §4)
- Always append the new fields, even when they are zero, using the emitter's existing key style.
- The fields go into the native log only. No FFI struct changes and no Qt rebuild.

**Concurrency**
- Everything runs on the decode worker thread.
- The probe mutex is already shared with the summary reader. The change adds one lock per frame, in addition to the existing three.
- No new threads. Retirement is untouched.

**Cost**
- Two vDSO `Instant` reads.
- One or two `vkGetSemaphoreCounterValue` calls (each a syncobj query, a few µs).
- One mutex lock.
- Total well under 0.1% of an 8 ms residence.

## 2. Current-state analysis

The supplied flow is:

`session.rs::record_submission` → `decode_frame`/`poll_decoder` → `ffmpeg.rs::drain` → `receive_frame` → `convert_frame` → `VulkanCopyPool::copy` → fence completion → `record_decoded_outputs` → `enqueue_frames`.

## 3. Design

### Decoder-owned measurements

Add private `VulkanFrameTimingProbe` in `timing.rs`, owned through an optional field on the existing FFmpeg decoder `Self`.

Read proposed `OPENNOW_VULKAN_FRAME_TIMING=1` once during construction, under the existing Vulkan feature. Enable only for a shared-device decoder. Default is disabled; disabled operation performs no additional clock reads.

The probe owns:

- A process-unique decoder-instance ID and increasing batch sequence.
- Current codec, decoder-mode label, and actual output format.
- Up to `STAGE_SAMPLE_CAPACITY` paired nanosecond tuples: `(receive, conversion, fence_wait)`.
- Batch UTC bounds and failed-conversion count.

It stays on the decoder worker; no mutex, worker thread, or packet hooks are needed.

In `drain`, time each successful `receive_frame` and its immediately following `convert_frame`. Record successful Vulkan conversions only. Conversion failures remain errors and increment the diagnostic failure count. EAGAIN contributes no successful-frame sample.

### Fence boundary and binding

Preserve `copy`’s signature. Add two internal interfaces:

- `enable_frame_timing(&mut self)` — called after lazy pool creation when enabled.
- `take_fence_wait(&mut self) → Option<Duration>` — consumes the latest observation.

Clear the observation at each copy attempt. Time exactly `wait_for_fences`, including failures; consume it after the conversion attempt. Failed attempts never enter successful-frame distributions.

Bind records only after successful Vulkan conversion, using `mode.label()`, `codec.label()`, actual dimensions/pixel format, and successful adopted-device validation already performed by `copy_frame`.

Preserve source retention, locks, semaphore updates, timeout, invalidation, retirement, and `with_completed_gpu_copy()` ordering.

### Reporting and interpretation

Reuse `summarize` for **nonoverlapping 256-frame batches**, then clear samples. Emit bounded numeric records to the existing native log, outside measured stages; logging failure must not fail playback. Discard partial batches upon decoder destruction or format change.

Include stage sums alongside percentiles. Analyze only complete batches wholly inside the observation window. Quantiles remain batch quantiles; never subtract percentiles or call them full-window percentiles.

Define host-wait dominance as:

`sum(fence_wait) > ½ × sum(receive + conversion)`

This classifies successful output processing only. Codec submission and asynchronous GPU decoding remain unattributed.
